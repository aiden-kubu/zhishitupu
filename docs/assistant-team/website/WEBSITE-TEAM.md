不将 I2 所有缺口改写为通过。当前授权包括新任务准备、接口设计、前端与必要只读接线的开发；真实数据库、真实模型和部署由另外明确的运行批次接入。所有任务严格串行；已有 06 桌面任务不被新子任务替代。

## 模型与会话事实

负责人要求总控 `GPT-6.1 Sol / Ultra`，并启用其所称 `1.5x` 快速档；新子任务 `gpt-6.1-sol / high`。2026-09-30 总控通过当前桌面窗口的 Windows UI Automation 读取到总控模型按钮为 `GPT-6.1 Sol Ultra`，07～09 创建前、07 正式派发前均读取到 `GPT-6.1 Sol 高`。这是桌面设置观察，不追溯证明历史批次或后端实际推理参数；速度菜单只观察到“启用标准模式”的开关为 On，尚无明确的 `1.5x` 标签证据，不据此推断倍率、不承诺速度倍数，不用 API 档位自动替代桌面 Ultra。

负责人已明确要求“子会话在本项目内建立可视的独立会话”。当前工具目录没有 create_thread、send_message_to_thread、read_thread、wait_threads 等桌面聊天管理入口；本批通过既有桌面应用公开可见的项目新聊天按钮、模型按钮、消息输入框和重命名命令操作，不启动 App Server，不使用会话内临时 Agent 替代。会话是否创建以真实项目侧栏条目及登记回执为证；没有聊天管理工具返回的 ID 时只记录核实的可见标题，不编造 ID。

独立聊天归属现有 `Java知识图谱` 项目，应用默认项目目录可能仍为主项目；任务消息要求每条命令显式使用指定独立工作树的 workdir，主项目及其他工作树只读，不假称应用默认目录已改变。创建和正式派发前核对该聊天的桌面模型按钮为 `GPT-6.1 Sol 高`。

阶段结束必须写任务单指定报告并发最终回报，然后停止，不自行派生任务。总控在当前工作期间直接读取共享工作树报告并查看桌面回执，审核后向同一会话发送下一阶段提示词；这减少人工转录，但不等于已有正式跨聊天消息 API 或离线常驻唤醒服务。桌面操作须核对目标身份、当前输入和发送按钮，不采用盲点坐标、内部数据库或未公开接口。执行台账见本目录 `DISPATCH-STATUS.json`。
