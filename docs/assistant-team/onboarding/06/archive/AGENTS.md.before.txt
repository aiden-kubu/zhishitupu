# 项目长期协作边界

适用于本项目后续 I2～I7、W2 及以后阶段。首次接入智能助手任务、尚未完整了解规则时，必须完整读取：

- [项目协调规则](D:/知识图谱/docs/assistant-team/COORDINATION.md)
- [总控职责、报告规则与交接记录](D:/知识图谱/docs/assistant-team/CONTROLLER-RULES.md)

后续复用已完成的阅读/审查结论，不因新一轮对话而重复全文审查。文档、代码、测试结果或证据变化时，仅检查变化及其影响范围；必要扩大时说明原因。使用明确版本/hash 或已知补丁标识基线，不仅凭 Git diff 判断未跟踪文件未变；常规小改不默认全仓扫描。相关回归测试是否重跑按代码影响判断，不把旧绿灯自动套用到新代码。

总控负责规划、任务单、技术复核、受控汇集、统一回归和获批的跨领域集成，不代替原 01～05 修改领域源码、SQL 或领域测试。领域所有权：01 ingestion/source、02 quality、03 research、04 learning、05 assessment；文件在主项目或哪个工作树都不改变所有权。

领域补修必须由总控准备完整指令，负责人手动转发对应原桌面任务，原任务执行并停止后再由总控复核。严格串行；不创建替代任务、不启动新的 App Server、不因无法派发而进入领域工作树代做。归属有争议先向负责人说明。

领域任务模型要求 `gpt-6-sol / high`；没有可靠的本轮实际设置证据时必须写“实际模型未核实”，不得把任务单要求、旧回执或工作树归属当作已核实。

每次报告分别列出实际代码修改者、测试运行者、真实环境验证者、模型要求及核实状态。最终验收由负责人确认。拥有职责不等于已有本阶段执行授权；不得自动进入后续阶段。

涉及前端时还须完整读取 `frontend/AGENTS.md`。不得覆盖已有修改或改写历史冻结 hash；受控变更使用明确授权和新增量记录。
