## 4. 五个领域的数据流：有实现基础，不是假装全流程已上线

```text
01 资料/任务/恢复与原文读取 ── 同一批真实对象、chunk/hash ──┐
既有图谱与原文 ──────────────────────────────────────────┤
                  03 A独立取证   03 B独立取证            │
                       └──── 03结构化比较 ────┐           │
                                            ↓           │
                            02 直接成果/来源核查 ←───────┘
                             ↓                   ↓
                03原始成果 + 02宿主原始核查观察 → 04
                                      04未保存路径/讲解/练习
                                               ↓
                              05可信04素材 + 当前路径/来源重读
                                         → 未执行测评候选
```

01提供数据/状态前置支持，不是每个任务都必须先执行01；02也能单独读取复审快照。每次编排只声明必需的直接依赖。04要同时消费研究原成果与质量原观察时，两者都须由宿主确认属于该消费任务直接依赖，不因“经过02”就允许无限传递全局成果。

Artifact是结构化交付物；模型摘要不等于证据。EvidenceRef承载真实对象/范围/定位/version或hash；宿主捕获的原始工具观察构成信任核对基础。A/B一方失败保留另一方，比较阻断；允许partial时下游持续携带缺口。引用有效仅证明身份/归属/当前内容，不证明语义正确。

这些交接的领域代码是真实Java实现，现有测试以fake宿主/fake仓储/mock JDBC/确定性DecisionProvider验证。没有生产全链路运行，也没有新增第五、第六个并行开发会话。
