## 后续装载边界

I2另行批准后，先用项目迁移创建专用、可丢弃的真实MySQL验收库；不连接现网、不复用用户业务数据。明确环境和备份/回滚后才准备装载器。当前没有SQL导入脚本，没有迁移变更。

JSON是逻辑样本，不是既有API请求体。后续映射为 knowledge_libraries / documents + document_metadata + document_topic_assignments / document_units + document_chunks / ingestion_jobs + candidate表 / knowledge_nodes + library_nodes + node_evidence / knowledge_edges + edge_evidence / learning_paths + learning_path_steps + learning_assessment_attempts。候选实际表名和必填列以现有迁移再次核对为准；缺省列、时间、文件存储位置、ID冲突、外键和索引需装载器验证，不允许关闭约束来“通过”。

基础数据与故障变体分开使用，每条故障场景从干净基线开始。V_BAD_STEP_OWNER 是仓储故障注入；V_HIGH_ID_EQUAL 是进程内对象探针；V_FORGED_HOST 是后续宿主探针。它们不能靠向正式表插入不合法行来模拟。V_LONG_A 为确定性派生正文，必须同时重算hash、单元偏移与文件内容。

现有local-default为共享旧路径，不具有用户归属；I2仅在隔离验收库由授权验收角色观察，不能宣称多用户隔离。路径1000中的旧90分、visitedAt和current状态故意并存，检查新模块只报告旧事实、不据此自动推进。

## 验收记录规则

每次执行记录：环境/构建hash、基础样本hash、使用变体、操作者、时间、请求/响应或页面截图、零业务写入证据、实际结果、负责人结论。真实模型只比较事实、引用、状态和边界，不要求逐字一致。浏览器网络记录只是一个层面的证据，I7还需数据库业务表前后校验；宿主允许的运行审计/临时记录须另外列明，不能混入业务写入。

154项现有Java回归使用各自fake/mock数据；它们未自动改为读取本样本包。本轮样本检查仅验证结构、引用、原文/hash与预期清单的一致性，后续真实数据库、宿主和网站结果均待实测。最终“通过/不通过”由项目负责人确认。
