## 3. 实现和语义复核

实际实现差异只在 insight 尾部：

1. 将 Q09 已有端点集合 SQL 文本提取为局部字符串，供 Q09/Q10 组合使用；提取前后 Q09 生成 SQL 不变。
2. Q10 由原逐节点双端 OR 的 NOT EXISTS 改为可见边端点集合与可见节点的反连接。
3. Q01～Q08 文本/绑定未改，Q09 SQL 未改；仍为原顺序十次查询。权限辅助方法、范围校验、其他公开查询方法未改。

静态等价依据：

- visible_nodes 的真实节点主键唯一；选库通过原 EXISTS 范围约束，不因共享归属重复节点。
- visible_edges 仍为 active 且双端 INNER JOIN 可见节点的边。端点若为 null 不可能通过这些连接；与可见节点主键匹配的端点集合不会引入 null 身份。
- “没有可见有效边以该节点为任一端点”与“该节点不在可见有效边端点集合中”等价。端点集合去重只用于判定有无，不改变排名中的真实边计度规则。
- 自环、反向/不同关系类型的边不会重复产生孤立列表项；范围外/inactive 边不能消除当前范围孤立性。
- Q10 仍返回原字段和 degree=0，以数值 n.id 升序、isolatedLimit 截断，Long/字符串映射原样。
- Q09 无 LIMIT，仍独立于列表和排名限制；异常继续上传，不吞错返回 0 或缓存值。

以上是针对差异的代码/集合语义推理，不替代 MySQL 对真实样本的 SQL 正确性和优化器选择验证。
