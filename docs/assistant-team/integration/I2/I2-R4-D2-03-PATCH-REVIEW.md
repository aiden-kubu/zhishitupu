## 3. 差异与语义审核

| 对象 | 实际变化及审核结论 |
| --- | --- |
| `JdbcResearchReadRepository.edges()` | 新增有文档范围的两个 DISTINCT CTE 和三次 ID 连接；无文档分支保持原 SQL 构成。变更止于边查询构造。 |
| `nodeScope` / `edgeDocumentScope` / `documentScope` | 函数体未变；有文档分支仍分别计算节点及边的正式来源、库/资料/节点条件。非边调用者不受此次改写影响。 |
| 既有仓储测试 | 仅获批 `edgeQueryChecksBothEndpointsAndRealEvidenceBeforeLimit` 调整 SQL 结构断言；原双端直接条件改为同一节点集合对 source/target 的两次约束，并检查独立边集合。其余四项未改。 |
| 新增定向测试 | 5 个方法：文档条件/分页前交集、incident/资料-only、无文档旧路径、映射/Long ID/limit+1、异常传播。它们不是 5 项真实 SQL 性能测试。 |

等价性依据：令 N 为按原 `nodeScope` 判断后唯一的节点 ID 集，E 为按原 `edgeDocumentScope` 判断后唯一的边 ID 集。原 WHERE 对 source、target、edge 分别要求满足 N、N、E；新查询用三个唯一 ID 内连接表达同一交集。没有把两端/边的 documentId 或 chunkId 联成必须相同，也没有将 OR/EXISTS 的含义改变为需要多个证据同时成立。

CTE 的 ID 唯一性使多个证据/多库归属不倍增外层边；自环只匹配一条自身边，各不同 edge ID 的反向边或不同关系类型不会被按端点合并。方向表达式、真实 `has_source`、字段映射、原状态处理、最终 `ORDER BY e.id LIMIT :maxRows` 及 window 包装均保持。过滤在最终 LIMIT 前的关系语义不变，不要求数据库采用某种固定物理连接顺序。

`DISTINCT` 可阻止 CTE 合并、材料化可能延迟并带有优化器内部索引，具有 [MySQL 8.4 官方文档](https://dev.mysql.com/doc/refman/8.4/en/derived-table-optimization.html)依据。但是否因此改善本实例性能仍属假设；不得写成已取得候选执行计划。优化器内部临时结构也不等于授权执行建索引 DDL。
