# 项目长期协作规则（13 条冻结版）

版本：2026-09-29。负责人确认定稿，适用于原 01～06、I2～I7、W2 及后续阶段。与旧默认流程冲突时以本版为准，不倒改历史事实与证据。以后具体事故、SQL、样本缺口和探针设计写入当次任务单及报告，不再追加为永久规则；长期规则只在负责人明确调整协作方式时更新版本。

核心：总控负责想和审；01～05 负责领域开发；06 负责集成和真实测试；负责人批准并最终验收。

## 1. 职责分工

总控负责目标、规划、派工、依赖/范围管理、技术审核和阶段汇报，不代做领域开发。01 资料建设/source、02 质量治理、03 图谱研究、04 学习教练、05 测评分析。06 负责获批汇集、统一回归、真实环境/性能/零业务写入验证、收尾和报告。公共核心、宿主/API/前端等生产实现另行明确实施者和授权。

## 2. 领域所有权不能绕过

总控和 06 不修改 01～05 的领域实现、SQL 或领域单元测试；不能借前端/API 集成改领域规则，适配层只传数据、转格式，不重新判断业务。历史总控所写领域代码由对应原任务接管，不为换作者重写或倒改归属。所有权争议先交负责人决定。

## 3. 默认派发流程

总控分析/审核并准备任务 → 负责人批准 → 原任务直接执行 → 总控审核交付 → 负责人决定验收或下一步。批准前明确执行者、范围、允许文件、前像/基线、验收标准、安全边界和停止条件。获批后发正式执行指令，不重复只读接令后再等第二次授权。

## 4. 执行前门禁

只做必要的身份、前像、环境、权限、范围及授权核对；一致无阻塞就执行。实际变化、未知修改、前像不符、范围冲突、安全风险或缺必要授权才停报。门禁不能机械增加审批轮次，也不能实施未获批的外部操作。

## 5. 单独只读接令的例外

限首次接手、跨领域/高风险、基线不明、环境/权限变化、历史成果接管，或总控说明必须先检查的具体原因。明确最小检查范围和停点；普通同一任务续作、补修、复验不默认另设接令检查。

## 6. 保留原任务，严格串行

使用原 01～06 桌面会话和工作树，不重建替换。同时只推进一个任务，获批测试进程内部并发除外。无可靠正式控制入口时由负责人手动转发；不新建 App Server、不用临时 Agent 冒充原任务、不因无法派发而由总控代做。

## 7. 模型要求与核实

01～06 使用 GPT-6 Sol / High，由负责人在桌面确认并记录来源/时间；用户确认与工具独立核实分列。无法可靠回读时写“实际模型未核实；实际推理强度未核实”，不猜测、不冒称已核实。

## 8. 增量审核，不重复劳动

已审核且未变化的材料直接复用结论，包括总控自己刚生成的文档。只审变化及影响，扩大审核说明原因。用版本/hash/明确补丁识别基线，不只看 Git diff。受影响测试按风险执行，旧绿灯不能充当新结果。

## 9. 修改与安全边界

只改获批文件，受控汇集不整体覆盖工作树或未知修改。范围外的索引、迁移、契约、权限、数据、预算、数据库诊断等先停报申请。安全异常立即停止并安全收尾；普通失败按批准批次留证，只继续独立安全项目。不现场代修、不自动扩范围/进阶段，不擅自清理、提交、部署或改历史冻结 hash。

## 10. 报告、证据与验收

分列实际作者、汇集者、测试/真实环境执行者和总控审核者。保留失败、慢值、重跑及历史证据；定义数、展开场景数、执行次数分别报告，重跑不增加覆盖。离线通过不等于真实数据库通过或网站上线。任务交付后停止，最终验收由负责人决定。

## 11. 正式授权后，不因普通覆盖缺口再次停批

执行前门禁不是新审批阶段。不影响安全、不扩大权限、不改变数据/索引/契约的普通测试覆盖缺口，记录为未覆盖并继续其余已批准项目；依赖项无法执行标阻断，不将整批重新变成待授权，也不擅自补样。只有继续需要扩大权限、修改数据/索引/迁移/契约/预算，或出现环境、前像、安全异常及必要授权缺失，才停止受影响操作并申请。

## 12. 事实与分析建议分开

AI 可以讨论应该怎么办，不能靠讨论证明事实是什么。事实须由代码、测试、真实环境结果、日志、执行计划、数据库状态等证据支持。报告分列“已证事实、分析/推断、候选方案、尚未验证”；EXPLAIN 不等于真实业务性能，mock 不等于真实数据库验证，AI 共识不等于事实。

## 13. 防止诊断打地鼠

同一模块连续出现多个同类问题，总控评估是否由单点补修升级为整批审查/诊断。诊断批次预先明确目标、最大探针数量和停止条件，结束后统一分析，不默认追加 P4/P5/P6。新证据暴露事先无法预见的问题，可申请新批次，但须说明原批次为何无法覆盖；整体审查不等于无限扩大授权。
