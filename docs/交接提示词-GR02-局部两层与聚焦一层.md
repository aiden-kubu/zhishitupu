## 一、最新用户决策

图谱三种模式固定为：

| 模式 | 固定范围 | 用途 |
|---|---:|---|
| 全局 | 全局总览 | 浏览全局代表性节点 |

| 聚焦 | 深度 1 | 查看当前节点及直接关联 |

## 六、实施要求

### 1. 固定模式与深度映射

在 `knowledge-graph/frontend/src/composables/useGraphWorkspace.ts` 中建立唯一规则：

```ts
const targetDepth: 1 | 2 = next === 'local' ? 2 : 1
```

要求：

- `setMode('local')` 固定生成 `mode=local&depth=2`。
- `setMode('focus')` 固定生成 `mode=focus&depth=1`。
- 两种模式继续使用已经落地的“`selectedNodeId` 优先、`centerNodeId` 兜底”规则。
- 两者都没有时保持当前有效视图，不生成无中心的伪局部/伪聚焦状态。
- `setMode('global')` 继续回到 `/` 并加载总览。

不要把单击节点改成自动请求。单击仍只负责选中、高亮和切换 AI 上下文；点击“局部/聚焦”后才按固定深度重载。

### 2. 删除可变深度状态和入口

既然模式已经决定深度，工具栏不应再显示“深度 1 / 2”。

在下列文件删除只为手动深度切换服务的内容：

- `knowledge-graph/frontend/src/features/graph/GraphToolbar.vue`
  - 删除深度选择 UI。
  - 删除 `depth` prop。
  - 删除 `update:depth` emit。
- `knowledge-graph/frontend/src/views/Graph/GraphView.vue`
  - 删除传给工具栏的 `:depth`。
  - 删除 `@update:depth`。
  - 删除不再使用的 `depth`、`setDepth` 解构。
- `knowledge-graph/frontend/src/composables/useGraphWorkspace.ts`
  - 删除 `setDepth()` 及其导出。
  - 清理只为深度按钮服务、已不再需要的可变状态。

允许保留 `focusNode(nodeId, targetDepth)` 的深度参数，因为后端邻域接口仍需要明确的 1 或 2；但该参数只能来自模式固定映射或双击扩展，不再来自用户可变深度控件。

清理应以 TypeScript 实际使用情况为准，不保留无调用的死代码，也不要顺势重构其他状态。

### 3. 路由解析必须服从模式，而不是服从任意 depth

`applyRouteQuery()` 必须按 `mode` 决定实际深度：

```text
mode=focus -> depth=1
mode=local 或缺省的节点邻域模式 -> depth=2
```

不能继续直接信任 URL 中任意组合的 `depth`。至少处理：

- `mode=local&depth=1`：实际按局部深度 2，并把 URL 规范为 `depth=2`。
- `mode=focus&depth=2`：实际按聚焦深度 1，并把 URL 规范为 `depth=1`。
- 缺少 `depth`：补为该模式的固定值。
- 非法 `mode`：按局部处理并规范为 `mode=local&depth=2`。

规范 URL 时使用现有 Vue Router，不刷新整页；避免规范化过程重复发起两次相同邻域请求。如果先 `router.replace()`，应结束当前解析，让路由 watcher 处理规范后的 URL。

邻域成功加载后继续保留 GR01 已实现的选中节点与中心节点对齐逻辑。

### 4. 所有“跳转并聚焦”入口改成聚焦一层

以下入口语义都是定位一个具体节点，应统一生成：

```ts
query: { node: String(nodeId), depth: '1', mode: 'focus' }
```
