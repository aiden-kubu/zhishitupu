# 项目变更记录

本文件用于持续记录项目实际发生的新增、修复和删除，方便后续接手、回归与追踪。

## 记录规则

1. 一次只实施一个小批次；当前批次验证通过后，再开始下一批。
2. “变更记录”只写已经实际完成的内容；尚未实施的工作写入“分批计划”。
3. 每项变更必须写明类型、影响范围和真实验证结果，不使用“应该通过”等推测性表述。
4. 删除数据、文件、接口或功能时，必须记录精确目标、影响、备份及恢复方式；破坏性操作仍需事先获得用户确认。
5. 新增依赖必须单独记录名称、版本、用途和许可证，并遵守项目的事前确认要求。
6. 不记录密钥、密码、个人数据或完整本机敏感路径。

状态统一使用：`待实施`、`进行中`、`已完成`、`受阻`、`已取消`。

## 当前执行边界

- 下一批只执行 `B01`。
- `B01` 验收并记录完成前，不开始 `B02`～`B06`。
- 每个批次完成后，在上方“变更记录”逐项登记实际的新增、修复、删除和测试结果。
- 若实施中发现必须扩大范围，先把原因和影响记录为 `受阻`，再向用户说明，不自行合并多个批次。
