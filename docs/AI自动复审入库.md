# AI 自动复审与入库

2026-09-13 用户明确要求取消人工审核，由 AI 复审并自动入库。本决定覆盖旧开发文档的人工审核要求。

## 当前流程

资料解析 → AI 抽取 → 自动主题分类 → AI 复审（95–98%）→ 自动入库（99%）→ 已完成（100%）。新资料自动经过全部阶段，无需点击接受或确认入库。

复审使用已配置默认模型，独立构造第二轮提示与请求，逐项核对候选和数据库中的真实原文。每批最多 25 项，累计候选与证据字符预算 36000；单个候选证据不截断。原文、候选和模型判断均视为不可信业务数据，不执行其中指令。所有候选都必须得到明确布尔判断和理由；未知编号、重复判断、遗漏、非法 JSON 等均拒绝当前批，坏响应最多 3 次，失败不入库。

通过的知识点按现有主题分配入库；未通过知识点的关系也被排除。通过的候选状态、入库节点/关系、别名、证据、库关联和任务完成标记在同一事务提交。取消或失败不会产生半成品知识。重复启动受运行集合和数据库状态锁保护，重复完成任务返回 409。

## 数据和恢复

复审理由、判断、模型名和时间保存于每个候选的 edited_payload_json.aiReview，保留原有编辑字段，无新表或依赖。审核状态在全部复审成功后才统一落为 ACCEPTED/REJECTED（原已编辑且通过者保留 EDITED）。中途失败时已完成的复审理由保留供查看；再次复审会重新检查现有候选，无需重新解析文件。候选与正式节点保持不同生命周期。

- POST /api/processing/jobs/{id}/ai-review：启动旧待审核或失败/取消的候选任务。
- POST /api/processing/jobs/{id}/retry：存在候选则复审，否则按原路径重新处理。
- GET /api/review/jobs/{id}/ai-decisions：读取复审判断与理由。
- 旧人工修改、批量接受/拒绝、commit HTTP 入口返回 409，不再作为入库入口。
- /review 为只读的 AI 复审记录，支持资料选择、知识/关系切换、结果筛选、搜索、分页和原文证据展开。

复审期间继续支持取消；若服务在复审中被强制终止，可在处理中心取消旧活动状态后继续复审。系统不自动重跑已完成任务。

## 验证

131 项后端测试通过，包括抽取后自动复审入库、拒绝端点传播、非法/不完整判断阻止入库、失败后复用候选重试、入库异常回滚、并发启动与取消、重复入库保护；前端类型检查和构建通过。

浏览器使用本机现有 Playwright（当前无 Browser 插件），验证 localhost:5173/processing → 查看复审结果 → /review → 展开原文证据；桌面 1440×1000 与手机 390×844 均有有效内容，无框架错误遮罩、无控制台错误、无人工入库按钮，稳定布局无横向溢出。

真实 #63 完成验证：71/71 复审批次、1505 项判断全部完成；排除 34 条关系，知识实体全部通过；经入库去重后得到 610 个节点和 844 条关系，任务 COMPLETED / 100%。已验证节点和关系均有来源证据，处理中心100% → 复审完成记录 → 知识图谱链接可用。

统计修正：数据洞察 pendingReviewCount 仅包含仍关联真实资料、任务状态为 AWAITING_REVIEW/AI_REVIEWING/FAILED/CANCELLED 且候选为 PENDING 的实体与关系。已完成任务和孤立历史候选不参与待复审计数，历史记录保留。新增真实数据库回归，132 项测试通过；复审集成测试仅清理其自己新建的候选，避免新增孤立夹具。
