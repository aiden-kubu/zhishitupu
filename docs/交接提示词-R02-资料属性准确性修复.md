## 三、具体实施要求

### 1. 返回并展示真实更新时间

- 在后端 `DocumentService.DocumentView` 增加可空的 `updatedAt` 字段。
- 资料列表和详情查询都应读取 `document_metadata.updated_at`。
- 字段必须表示元数据行真实更新时间，不得在后端用 `documents.created_at` 冒充。
- 元数据不存在的存量资料允许返回 `null`。
- 前端 `DocumentDto.updatedAt` 保持可选或可空，并与实际响应一致。
- 界面有 `updatedAt` 时显示“更新 ……”；没有时显示“创建 ……”，不得继续显示“更新 createdAt”。
- 标题、生命周期、可信度发生保存后，接口返回的 `updatedAt` 应反映本次元数据更新。

### 2. 修正 SHA-256 表达

- 上传文件时只是计算并保存 SHA-256，用于标识和去重；没有与外部基准值或再次读取结果做一致性比对。
- 新上传资料的 `verification_json.hash` 建议保存：

  ```json
  {
    "sha256": "...",
    "recordedAt": "..."
  }
  ```

- 不要再为新数据写入 `matched: true`，不要使用会暗示比对成功的 `checkedAt`。
- 为兼容已有数据，前端类型可以继续容忍旧字段 `checkedAt`、`matched`，但界面统一只表达“SHA-256 已记录”或“哈希已记录”。
- 提示文字应明确为“上传时计算并记录 SHA-256”，不得出现“已校验”“一致”“匹配通过”等超出事实的表述。
- 不批量修改数据库存量 JSON，不重新读取或重算已有文件，不新增迁移。
- 同步纠正本批直接涉及的 `AGENTS.md`、注释或类型说明中的错误语义；不要扩写无关文档。

### 3. 支持取消人工校对

- 打开资料编辑弹窗时保留原始 `human.checked` 状态。
- 保存时，只要当前复选框值与原值不同，就调用已有验证接口；既要支持 `false → true`，也要支持 `true → false`。
- 取消时提交 `humanChecked: false`；后端已有的 false 状态写入能力应继续复用，不新增接口或表。
- 保存成功后用接口返回值更新列表，重新打开弹窗必须看到最新状态。
- 不顺带增加人工校对历史、操作人、权限或新弹窗。
