## 一、问题现象

复现路径：

1. 当前邻域中心为“栈”。
2. 在画布中单击选择“链接表”。画布已高亮“链接表”，底部显示“当前查看 链接表”。
3. 点击工具栏“局部”或“聚焦”。
4. 实际重新加载的仍是“栈”的知识，而不是“链接表”的邻域。

截图只用于说明现象，不是实施指令。

## 二、根因

问题位于：

`knowledge-graph/frontend/src/composables/useGraphWorkspace.ts`

当前画布单击只更新 `selectedNodeId`，这是合理的轻量浏览行为；但 `setMode()` 切换“局部/聚焦”时只读取：

```ts
subgraph.value?.centerNodeId
```

所以即使用户已经选择“链接表”，路由和邻域请求仍使用旧中心“栈”。`setDepth()` 也只读取旧中心，存在相同的目标节点不一致问题。此外，新的邻域加载完成后没有主动对齐 `selectedNodeId`，旧选择可能残留并影响后续操作。

## 三、唯一目标

建立一条简单且一致的目标节点规则：

```text
当前选中节点 selectedNodeId 优先；没有选中节点时，才使用当前子图中心 centerNodeId。
```

完成后：选择“链接表”再点击“局部”或“聚焦”，必须以“链接表”为新中心加载邻域，而不是继续显示“栈”。

|---|---|---|
| 选中“链接表”后切换“局部” | 直接可见 | 画布中心和底部中心卡片变成“链接表” |

| 旧选中状态清理 | 不容易直接看到 | 后续模式/深度操作不会又跳回“栈” |

## 六、实施要求

### 1. 模式切换优先使用当前选中节点

在 `setMode(next)` 中，非全局模式的目标节点必须使用：

```ts
const targetNodeId = selectedNodeId.value ?? subgraph.value?.centerNodeId
```

点击“局部”或“聚焦”时：

- 有选中节点：使用选中节点作为路由 `node`。
- 没有选中节点：使用当前子图中心作为兜底。
- 两者都没有：不要把界面切成一个没有中心的伪局部/伪聚焦状态，保持当前有效视图即可。
- “局部”继续使用当前 `depth`。
- “聚焦”固定使用深度 `1`。
- URL 仍使用现有格式：`/?node={id}&depth={1|2}&mode={local|focus}`。

不要修改 `selectNode()` 让每次单击都立即请求邻域；单击仍只做选中和 AI 上下文切换，用户点击“局部/聚焦”后才重载子图。

### 2. 深度切换使用相同目标规则

在 `setDepth(next)` 中同样使用：

```ts
selectedNodeId.value ?? subgraph.value?.centerNodeId
```

这样用户在局部图中选择另一个节点后点击深度 `1/2`，深度变化会应用到当前选择，不会继续应用到旧中心。

全局模式下仍不得因点击深度而加载局部子图。

### 3. 邻域加载成功后对齐选中节点和中心节点

通过 URL 加载某个节点邻域成功后，将 `selectedNodeId` 对齐到这次实际请求的中心节点，避免上一次子图的选择残留。

要求：

- 只在邻域请求成功、子图已经赋值后对齐。
- 失败路径继续清空无效选择并保留现有错误处理。
- 全局总览继续清空 `selectedNodeId`。
- 不增加全局状态库、缓存层、事件总线或新 composable。

可在现有 `focusNode()` 成功分支中做最小修改。不要为了这个问题重构整套工作台状态。

### 4. 保持已有行为

- 单击节点：高亮节点并更新 AI 上下文。
- 双击节点：按现有逻辑加载深度 2。
- 点击空白：取消选中强调。
- 全局：加载总览并清空选中。
- 重置：回到全局。
- 2D/3D 切换：保持当前中心和选择。
- 搜索跳转：继续按 URL 指定节点加载邻域。
- WebGL 失败：继续回退 2D。
