## 三、实施要求

### 1. 人工校对双向保存

在 `knowledge-graph/frontend/src/views/Library/LibraryView.vue` 的 `saveDocEditor` 中：

- 进入函数并确认编辑对象存在后，立即把当前对象保存到局部常量，例如 `const editor = docEditor.value`。
- 后续异步流程使用这个局部快照，不要在 `await` 后无保护地继续读取 `docEditor.value`。
- 原始状态使用：

  ```ts
  const originalHumanChecked = editor.doc.verification?.human?.checked ?? false
  ```

- 当前值与原始值不相等时才调用 `setDocumentVerification`：

  ```ts
  editor.humanChecked !== originalHumanChecked
  ```

- 请求载荷必须传当前真实值，而不是写死 `true`：

  ```ts
  humanChecked: editor.humanChecked
  ```

- 只有勾选时才发送“编辑资料时标记人工校对”的 note；取消勾选时 note 省略。
- 接口成功后继续使用返回的 `DocumentDto` 更新资料列表。
- 请求结束时，仅当当前仍在编辑同一资料时才关闭弹窗；用户已取消或切换其他资料时，不要误关后来打开的弹窗。

不要改后端接口。`PUT /api/documents/{id}/verification` 已支持并通过测试验证 `humanChecked=false`。

### 2. 对齐可空类型

在 `knowledge-graph/frontend/src/services/types.ts` 中把资料更新时间改为：

```ts
updatedAt?: string | null
```

不要重新引入以 `createdAt` 冒充更新时间的逻辑。现有界面在 `updatedAt` 为空时显示“创建时间”的行为应保留。
